# 4. Tối ưu hóa tài nguyên GPU và cơ chế Sharing
Trong các hệ thống Cloud Native AI, GPU là tài nguyên đắt đỏ nhất. Tài liệu này hướng dẫn cách cài đặt NVIDIA GPU Operator và cấu hình Time-Slicing để cho phép nhiều Pod cùng chia sẻ một GPU vật lý.

## 1. Tại sao cần GPU Sharing?
Mặc định, Kubernetes cấp phát GPU theo cơ chế độc quyền: 1 Pod = 1 GPU. Tuy nhiên:

* Nhiều mô hình Inference nhỏ (như BERT, ResNet) không dùng hết 100% hiệu năng của một GPU mạnh (như A100 hay L4).

* Trong môi trường phát triển (Dev/Lab), việc mỗi sinh viên/kỹ sư chiếm dụng riêng 1 GPU gây lãng phí lớn.

Giải pháp: Sử dụng Time-Slicing để chia một GPU vật lý thành nhiều "lát cắt" thời gian, giúp tăng số lượng Pod có thể chạy đồng thời.

## 2. Cài đặt NVIDIA GPU Operator
Đây là bộ công cụ tự động hóa toàn bộ việc quản lý driver và phần mềm hỗ trợ GPU trên Kubernetes.

### 2.1. Thêm Helm Repository
```bash
helm repo add nvidia https://helm.github.io/gpu-operator
helm repo update
```
### 2.2. Cài đặt cơ bản
```bash
helm install gpu-operator nvidia/gpu-operator -n gpu-operator --create-namespace
```
## 3. Cấu hình GPU Time-Slicing
Để kích hoạt tính năng chia sẻ, chúng ta cần định nghĩa một chiến lược chia sẻ thông qua ConfigMap.

### 3.1. Tạo file cấu hình time-slicing-config.yaml
Ví dụ dưới đây chia 1 GPU vật lý thành 10 GPU ảo (replicas):

```YAML
apiVersion: v1
kind: ConfigMap
metadata:
  name: device-plugin-config
  namespace: gpu-operator
data:
  any: |-
    version: v1
    sharing:
      timeSlicing:
        resources:
        - name: nvidia.com/gpu
          replicas: 10
```
Lưu ý: Bạn có thể thay đổi replicas tùy theo dung lượng VRAM của GPU hiện có.

### 3.2. Áp dụng cấu hình vào Operator
Cập nhật GPU Operator để nó nhận diện và sử dụng ConfigMap này:

```bash
kubectl apply -f time-slicing-config.yaml

helm upgrade gpu-operator nvidia/gpu-operator \
  -n gpu-operator \
  --reuse-values \
  --set devicePlugin.config.name=device-plugin-config
```
## 4. Sử dụng GPU trong ứng dụng AI
Sau khi cấu hình xong, các Pod có thể yêu cầu tài nguyên GPU như bình thường. Kubernetes sẽ tự điều phối chúng vào các "lát cắt" đã tạo.

Ví dụ file Deployment:

```YAML
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ai-inference-service
spec:
  template:
    spec:
      containers:
      - name: model-container
        image: pytorch/pytorch:latest
        resources:
          limits:
            nvidia.com/gpu: 1 # Yêu cầu 1 GPU ảo
```
## 5. Kiểm tra và giám sát
Sau khi triển khai, bạn có thể kiểm tra xem Kubernetes đã nhận diện đủ số lượng GPU ảo chưa:

```bash
# Kiểm tra tài nguyên của Node
kubectl describe node <tên-node> | grep -A 5 "Capacity"
# Kết quả mong đợi: nvidia.com/gpu: 10 (thay vì 1 như trước)
```
### 6. Lưu ý quan trọng khi dùng Time-Slicing
* **Cách ly bộ nhớ (VRAM):** Time-Slicing chỉ chia sẻ thời gian tính toán, không cách ly bộ nhớ. Nếu một Pod chiếm hết VRAM, các Pod khác trên cùng GPU vật lý có thể bị lỗi Out Of Memory (OOM).

* **Hiệu năng:** Vì dùng chung tài nguyên, các tác vụ tính toán nặng chạy song song sẽ làm tăng độ trễ (latency) của mô hình.

* **MIG (Multi-Instance GPU):** Đối với các dòng GPU cao cấp (như A100, H100), nên cân nhắc sử dụng công nghệ MIG để cách ly cả phần cứng và bộ nhớ một cách tuyệt đối (thay vì Time-Slicing).
