# 7. Cách xây dựng Helm YAML và công cụ Helmify

Việc triển khai ứng dụng trên Kubernetes đòi hỏi chúng ta phải viết các file cấu hình YAML. Khi ứng dụng trở nên phức tạp, số lượng file YAML tăng lên, việc quản lý và tùy biến chúng cho các môi trường khác nhau (Dev, Staging, Prod) trở nên khó khăn. Đây là lúc Helm phát huy tác dụng.

## 1. Cấu trúc cơ bản của một file Kubernetes YAML

Dựa trên hướng dẫn từ bài viết [How to write a YAML file in Kubernetes](https://www.linkedin.com/pulse/how-write-yaml-file-kubernetes-megha-s-k/), mỗi file cấu hình K8s (Manifest) dù là cho Pod, Deployment, hay Service đều được xây dựng dựa trên 4 trường (fields) cốt lõi bắt buộc:

1. **`apiVersion`**: Chỉ định phiên bản của Kubernetes API mà bạn đang sử dụng để tạo đối tượng này (ví dụ: `v1`, `apps/v1`, `serving.kserve.io/v1beta1`).
2. **`kind`**: Xác định loại đối tượng (Object) bạn muốn tạo (ví dụ: `Pod`, `Deployment`, `Service`, `InferenceService`).
3. **`metadata`**: Chứa thông tin giúp nhận dạng duy nhất đối tượng, bao gồm `name` (tên), `namespace` (không gian tên), và `labels` (nhãn) để gom nhóm.
4. **`spec`** (Specification): Đây là phần quan trọng nhất, mô tả "trạng thái mong muốn" (desired state) của đối tượng. Ví dụ, với Deployment, bạn sẽ khai báo số lượng replicas, thông tin container (image, port, biến môi trường, tài nguyên CPU/RAM/GPU).

Ví dụ một file Deployment cơ bản:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: nginx:latest
```

## 2. Từ K8s YAML sang Helm Chart

Khi sử dụng Helm, chúng ta không viết các file YAML tĩnh nữa mà chuyển sang sử dụng **Templates**. Helm cho phép tham số hóa (parameterize) các giá trị trong file YAML bằng cách sử dụng Go templates.

Các giá trị cụ thể (như tên image, số replicas) sẽ được tách ra và lưu trong một file trung tâm gọi là `values.yaml`. Trong các file template (ví dụ `templates/deployment.yaml`), chúng ta sẽ gọi các giá trị này thông qua cú pháp `{{ .Values.thuoc_tinh }}`.

Ví dụ biến file Deployment ở trên thành Helm template:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Values.name }}
spec:
  replicas: {{ .Values.replicaCount }}
...
      containers:
      - name: {{ .Values.name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
```
Điều này giúp bạn có thể dễ dàng thay đổi cấu hình mà không cần chạm vào code YAML gốc.

## 3. Giới thiệu công cụ Helmify

Việc chuyển đổi thủ công từ hàng chục file K8s YAML thuần sang định dạng Helm template có thể rất tốn thời gian và dễ sai sót. Công cụ **[Helmify](https://github.com/arttor/helmify)** được sinh ra để giải quyết vấn đề này.

**Helmify** là một công cụ CLI giúp tự động chuyển đổi file K8s YAML thành một Helm chart hoàn chỉnh. Nó sẽ tự động tạo cấu trúc thư mục Chart, file `Chart.yaml`, `values.yaml`, và thay thế các giá trị tĩnh trong file YAML gốc bằng các biến template.

### Hướng dẫn cài đặt và sử dụng cơ bản

**Cài đặt:**
Bạn có thể cài đặt Helmify thông qua Homebrew, tải file nhị phân từ GitHub Releases, hoặc dùng `go install`:
```bash
brew install arttor/tap/helmify
# hoặc
go install github.com/arttor/helmify/cmd/helmify@latest
```

**Sử dụng:**
Cách đơn giản nhất là pipe (chuyển hướng) nội dung file YAML vào lệnh `helmify`, kèm theo tên thư mục chart bạn muốn tạo:

```bash
# Chuyển đổi một file YAML đơn lẻ
cat deployment.yaml | helmify mychart

# Chuyển đổi toàn bộ thư mục (kết hợp với kustomize hoặc awk)
awk 'FNR==1 && NR!=1  {print "---"}{print}' *.yaml | helmify mychart
```

Sau khi chạy lệnh, thư mục `mychart` sẽ được tạo ra với cấu trúc chuẩn của Helm, và bạn có thể ngay lập tức tùy chỉnh file `values.yaml` hoặc chạy `helm install` để triển khai. Đây là một bước đệm tuyệt vời để làm quen với Helm khi bạn đã có sẵn các file K8s YAML cũ.
