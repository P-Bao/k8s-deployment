# 8. Giải thích minh họa Helm Chart trên KServe

Trong bài này, chúng ta sẽ phân tích một Helm chart thực tế được xây dựng cho KServe tại `example/charts/kserve-stack`. Chart này được thiết kế theo dạng "Reusable standard-mode bundle", nghĩa là một bộ khung dùng chung để có thể triển khai nhiều mô hình AI khác nhau chỉ bằng cách cung cấp các file `values.yaml` khác nhau.

## 1. Tổng quan cấu trúc Chart `kserve-stack`

Một Helm chart chuẩn bao gồm các thành phần:
- [**`Chart.yaml`**](../example/charts/kserve-stack/Chart.yaml): Khai báo siêu dữ liệu của chart (tên `kserve-stack`, phiên bản, mô tả).
- [**`values.yaml`**](../example/charts/kserve-stack/values.yaml): Chứa các giá trị cấu hình mặc định cho toàn bộ stack (namespace, thông số tài nguyên GPU/CPU, cổng kết nối, cấu hình gateway).
- **Thư mục [`templates/`](../example/charts/kserve-stack/templates/)**: Chứa các file Go template sẽ được Helm biên dịch thành K8s YAML.
  - [`inference-service.yaml`](../example/charts/kserve-stack/templates/inference-service.yaml): Khai báo `InferenceService` (đối tượng cốt lõi của KServe) để chạy mô hình AI.
  - [`gateway.yaml`](../example/charts/kserve-stack/templates/gateway.yaml): Khai báo Deployment và Service cho thành phần định tuyến (nếu bật).
  - [`hpa.yaml`](../example/charts/kserve-stack/templates/hpa.yaml): Cấu hình HorizontalPodAutoscaler để tự động mở rộng theo tải.
  - [`pvc.yaml`](../example/charts/kserve-stack/templates/pvc.yaml): Khai báo PersistentVolumeClaim để gắn ổ đĩa lưu trữ.
  - [`_helpers.tpl`](../example/charts/kserve-stack/templates/_helpers.tpl): Chứa các hàm hỗ trợ sinh tên (name, fullname) chuẩn xác.

**Sức mạnh của Chart dùng chung:** Bằng cách thiết lập [`inference-service.yaml`](../example/charts/kserve-stack/templates/inference-service.yaml) sử dụng toàn bộ biến từ `.Values.service.*`, chúng ta không cần viết lại YAML cho mỗi mô hình. Ta chỉ cần định nghĩa lại biến môi trường, tài nguyên, và image trong các file values riêng biệt (như `t2s-indextts2.yaml` hay `norm-openai.yaml`).

## 2. Minh họa 1: Triển khai Mô hình IndexTTS2 (Sử dụng GPU)

Mô hình IndexTTS2 yêu cầu tài nguyên GPU mạnh mẽ để tổng hợp giọng nói, và cần ổ đĩa để lưu trữ file âm thanh đầu ra. Chúng ta sẽ ghi đè cấu hình mặc định bằng file [`values/t2s-indextts2.yaml`](../example/charts/kserve-stack/values/t2s-indextts2.yaml).

### Cấp phát GPU
Trong [`values/t2s-indextts2.yaml`](../example/charts/kserve-stack/values/t2s-indextts2.yaml):
```yaml
resources:
  requests:
    cpu: "2"
    memory: "8Gi"
  limits:
    cpu: "6"
    memory: "16Gi"
  gpu:
    enabled: true
    count: 3
    resourceName: nvidia.com/gpu
```
Khi Helm biên dịch [`inference-service.yaml`](../example/charts/kserve-stack/templates/inference-service.yaml), khối lệnh sau sẽ xử lý phần này:
```gotemplate
{{- if .Values.service.resources.gpu.enabled }}
{{ .Values.service.resources.gpu.resourceName | default .Values.global.gpu.resourceName }}: {{ .Values.service.resources.gpu.count | default 1 }}
{{- end }}
```
Kết quả là Pod sẽ được yêu cầu cấp chính xác `3` lát cắt GPU (`nvidia.com/gpu: 3`).

### Cấu hình Auto-scaling theo GPU
Vì mô hình dùng GPU, việc auto-scale sẽ dựa trên mức sử dụng GPU:
```yaml
autoscaling:
  enabled: true
  minReplicas: 1
  maxReplicas: 1
  gpu:
    enabled: true
    metricName: gpu_utilization
    targetAverageValue: "70"
```
Trong [`hpa.yaml`](../example/charts/kserve-stack/templates/hpa.yaml), cấu hình này sẽ sinh ra chỉ số (metric) loại `Pods` tham chiếu trực tiếp tới `gpu_utilization` (được cung cấp bởi Prometheus Adapter) để scale up nếu tải vượt 70%.

### Gắn ổ đĩa lưu trữ (PVC)
Mô hình cần lưu file âm thanh. File values bật tính năng PVC và chỉ định `hostPath`:
```yaml
pvc:
  enabled: true
  create: true
  name: t2s-audio-pvc
  storageClassName: "manual"
  hostPath: "/home/iec/disk2/AnhLM027/Dev/T2S/T2S_V3/data"
  size: 200Gi
  mountPath: /data
```
Template [`pvc.yaml`](../example/charts/kserve-stack/templates/pvc.yaml) sẽ tự động tạo một `PersistentVolume` (loại hostPath) và một `PersistentVolumeClaim`. Sau đó, [`inference-service.yaml`](../example/charts/kserve-stack/templates/inference-service.yaml) sẽ mount PVC này vào đường dẫn `/data` bên trong container.

## 3. Minh họa 2: Dịch vụ Norm-OpenAI (Sử dụng CPU & API Key)

Dịch vụ này đóng vai trò như một proxy để gọi API của OpenAI thực hiện chuẩn hóa văn bản. Nó không chạy mô hình học máy cục bộ, do đó không cần GPU, chỉ tốn một lượng nhỏ CPU/RAM. Cấu hình được định nghĩa tại [`values/norm-openai.yaml`](../example/charts/kserve-stack/values/norm-openai.yaml).

### Tối ưu CPU/Memory và tắt GPU
```yaml
resources:
  requests:
    cpu: "100m"
    memory: "256Mi"
  limits:
    cpu: "500m"
    memory: "512Mi"
  gpu:
    enabled: false
```
Do `gpu.enabled: false`, phần cấp phát GPU trong template sẽ bị bỏ qua, tiết kiệm tài nguyên đắt đỏ cho cụm K8s.

### 3.3 Quản lý biến môi trường và Secret (API Key)

Dịch vụ này đóng vai trò như một proxy để gọi mô hình ngôn ngữ lớn (LLM). Thực tế trong mã nguồn của `norm-openai`, hệ thống sử dụng thư viện `google-genai` (Gemini), yêu cầu biến `GOOGLE_API_KEY`.

Để tránh rò rỉ khóa API vào Git, chúng ta có hai cách nạp biến môi trường lúc chạy:

#### Cách 1: Sử dụng Kubernetes Secrets (Theo chuẩn thực tế dự án)

Đây là phương pháp khuyên dùng. Bạn sử dụng `Makefile` để nạp toàn bộ cấu hình từ file `.env` vào một Secret chung:
```bash
# Lệnh này thực hiện: kubectl create secret generic t2s-secrets --from-env-file=.env
make secrets
```
Trong template [`inference-service.yaml`](../example/charts/kserve-stack/templates/inference-service.yaml), Secret này đã được cấu hình nạp tự động qua `envFrom`:
```yaml
envFrom:
  - secretRef:
      name: t2s-secrets
      optional: true
```

#### Cách 2: Tiêm từ biến môi trường của Shell (Dùng cho CI/CD hoặc Test nhanh)

Bạn có thể truyền trực tiếp giá trị từ môi trường Shell vào lệnh Helm bằng cờ `--set`. Cách này hữu ích khi bạn muốn ghi đè cấu hình mà không cần tạo Secret trên K8s:
```bash
source .env
helm upgrade --install norm-openai ./kserve-stack \
  -f ./kserve-stack/values/norm-openai.yaml \
  --set service.env[0].name="GOOGLE_API_KEY" \
  --set service.env[0].value="${GOOGLE_API_KEY}"
```

Cơ chế này hoạt động nhờ khối lặp `range` trong template sẽ tự động chuyển các giá trị từ `values.yaml` (hoặc từ cờ `--set`) thành biến môi trường:
```gotemplate
{{- range .Values.service.env }}
- name: {{ .name }}
  value: {{ .value | quote }}
{{- end }}
```
